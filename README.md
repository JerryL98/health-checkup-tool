## 这是什么

国家卫健委发布了《成人健康体检项目推荐指引（2025年版）》。但普通人拿到这份文件仍然不知道该查什么 —— 附件里的表格是按「疾病风险人群」组织的，你得先知道自己属于哪类风险人群，才能对应到该做的项目。

本项目把这个逻辑做成了一个**问答式工具**：

```
回答问卷  →  判定你命中的风险人群  →  输出分三档的体检项目清单
                 ↓
        每一项都标注「依据哪份文件的哪一条」
```

同时针对老年人，额外接入《老年人健康管理服务规范（2026年）》和 6 项老年卫生行业标准（WS/T），覆盖衰弱、肌少症、跌倒、认知、营养、多重用药等老年综合征。

## 为什么做这个

- **给子女用的**：父母说不清自己的病史和用药，问卷每一步都有「该问什么」的提示，可以拿着手机当面问。
- **给老人用的**：字号三档可调（默认 17px，按钮旁边写了「字号」，切换后会弹提示，设置会记住）、选项带序号、所有选项和输入框都有清晰边框、长句拆短、**267 个专业词都能点开看通俗解释**。
- **给「不想被过度检查」的人用的**：工具会明确告诉你哪些项目**证据不足、不推荐**，以及 74 / 75 岁以上为什么要谨慎。
- **要可核对**：每个结论都能回溯到原文。14 份依据文件全部内嵌在页面里，带排版可查阅、可下载。

## 功能

**问卷**
- 7 个步骤：开始之前 → 基本情况 → 健康与家族史 → 生活方式 → 专项问题 → 近期化验结果（选填）→ 老年健康评估
- 老年评估模块**只在 ≥60 岁、或自己勾选需要时**出现（58 岁但已衰弱的人也能进）
- 条件题：选了「吸烟」才出现支数 / 年数，选了「已戒烟」才出现戒烟年数
- 年龄、性别为必填并会校验，因为几乎所有风险判定都依赖这两项
- **每道题左侧有题号**（每页从 1 开始），题号和「朗读本页」里的「第 N 题」一致，方便电话里对号报给子女
- 选择题选项**带序号**，方便老人电话里报给子女
- 底部有「读给我听」（浏览器语音合成）

**风险判定**
- **18 类风险人群**：心脑血管、糖尿病、已确诊糖尿病、COPD、肺癌、结直肠癌、胃癌、肝癌、乳腺癌、前列腺癌、食管癌、甲状腺癌、卵巢癌、认知功能障碍、骨质疏松、慢性肾病、肥胖 / 代谢、腹主动脉瘤
- 评分量表：糖尿病风险评分、COPD 评分、结直肠癌评分
- 高风险 / 需关注 两级，各自标明命中的是哪一条

**输出**
- 网页结果页：**目录有两种形态，按屏幕自动切换** —— 宽屏横屏用**左侧常驻目录**（可一键收起成窄边栏）；竖屏 / 窄屏用**顶部常驻的可收起条**（吸在页头下面，默认收起，点一条后自动收起、随时可再展开）。收/展状态会记住 → 指标卡 → 高风险 → 建议项目（**基础项目 / 重点加查 / 可选项目** 三档，每项带出处）→ 「做多少」的提醒 → 挂号与科室指引 → 老年人专项 → 依据文件 → 免责声明
- **长图导出**（Canvas 本地绘制，无 html2canvas）：
  - 完整版：视命中风险数量而定，重档案约 11 000 px 以上
  - 精简版：约 4 500 px，只保留「基础项目汇总 + 建议加查项目汇总」
  - 图片**最上方**是「本测试依据《成人健康体检项目推荐指引（2025年版）》进行……」的声明
- **挂号与科室指引（详细版）**：
  - **5 步流程**：挂号 → 开单 → 预约 → 检查 → 复诊
  - 按你的风险自动列出该挂的科室，每个科室都写清 **常见别名**（不同医院叫法不同，可以直接念给导诊台听）、**进门可以怎么说**（一句现成的话）、以及一句提醒
  - **检查前准备对照表**：12 类检查要不要空腹、要不要憋尿、要不要肠道准备、要不要预约、要不要家属陪同
  - **随身清单**：身份证 / 医保卡、既往报告、全部药盒、这份清单本身
  - **常见问题**（可折叠）：医生说不用做怎么办、医院没有这个项目怎么办、一天做不完怎么办、报告异常是不是得病了、多久复查一次、有没有老年人优先通道

**查阅依据**
- 「📖 依据文件」栏目：14 份文件**全文带排版**（含附件4的流程图原图、附件5的评估指标表）
- 编号与页面各处的「依据 / 出处」标注一一对应
- **可下载**：5 份官方原件（.docx）+ 9 份本工具整理的 .docx，并可**一键打包下载全部 14 份（.zip）**
- 术语弹窗：**268 条**专业词条，每条都有通俗解释和对应的依据文件（其中 **157 条**还附了原文摘录，摘录全部自动取自内嵌的依据文件正文，可一键跳到原文核对）；弹窗顶部和底部各有一个明显的「✕ 关闭」，按 Esc 也能关

**无障碍 / 适老**
- 字号三档：A / A+ / A++（17px / 20px / 23px），按钮旁有「字号」标签、当前档位是实心色块、切换后有提示，跟随 localStorage 记住
- 所有选择项、输入框、按钮都有可见描边（对白底 ≥3:1，符合 WCAG 1.4.11），不再只靠浅灰填充
- 多选题标「可多选」、单选题标「单选」（原来只写在标题括号里，容易看漏）
- 「保存长图」弹层把提醒和按钮固定在屏幕上，不用滚动找按钮；弹层里同时给出「长按保存」和「下载图片」两条路
- **竖屏 / 窄屏**下，向下滑动时自动收起页签那一行（只留标题与字号），向上滑或回到顶部再出现 —— 把顶部固定占用的高度让给正文
- 页面标题可点击**返回首页**（不清空已填内容，与「重新开始」明确区分）
- 第三个页签「💡 关于/开源」：源码地址、许可协议（可做／必须做／不可做三栏）、照抄即可的署名格式、以及许可不覆盖的第三方材料说明
- 带打印样式，可直接打印成纸质清单

**关于第 9–14 项**：这些标准的正式文本是**收费出版物，官方未公开发布全文**。本项目因此：

- **只收录官方通告公布的适用范围等信息**，不收录全文
- 页面上**只标注「文档名 + 章节名称」，绝不标注条款号** —— 避免出现无法核对的引用
- 明确告诉用户「如需精确条款请查阅标准正式文本」

**证据把关**：附件3 的「可选项目」里列了一些证据不足的项目。本项目逐条对照国内外筛查指南后，把它们**从推荐清单里去掉，并在对应位置写明理由**：

| 项目 | 处理方式 |
|---|---|
| 异常糖链糖蛋白（TAP） | 无症状人群无筛查证据 → 剔除 |
| 乳腺热层析成像 | 指南明确不推荐用于乳腺癌筛查 → 剔除 |
| 肺癌肿瘤标志物（CEA / NSE / CYFRA21-1 等）、胸部 X 线片 | 不推荐用于肺癌筛查 → 剔除，肺癌只保留低剂量 CT |
| 血清胃蛋白酶原、胃泌素-17 | 保留但标注「只能用于风险分层，**不得单独用于胃癌筛查**」 |
| 总 PSA / 游离 PSA | 保留，但标注**必须医患共同决策**，并提示 70 岁以上或预期寿命不足 10 年一般不建议 |
| 甲状腺超声 | 保留但限定**仅高危人群**，注明不推荐普通人群普筛 |
| ApoE 基因检测 | 标注不推荐用于无症状人群的常规筛查 |

**「本工具补充」是什么意思？** 附件5 给出了各类风险人群的判定标准，但有 **5 类**没有单列：**腹主动脉瘤、骨质疏松、慢性肾病、肥胖 / 代谢、已确诊糖尿病的并发症管理**。这些筛查**项目**在附件3 里其实有，缺的是「什么情况算高风险」的**判定阈值**。本项目依据 USPSTF 2019、骨密度与 FRAX 相关指南、BMI / 腰围标准等公开依据补齐了阈值，并在页面上逐条标注 **「本工具补充」**，与官方原文来源明确区分。

## 隐私

- **全部计算在本机完成。** 风险判定、评分、长图生成全在浏览器里跑，没有任何后端。
- **不采集**姓名、电话、证件号、地址。
- **不上传**任何信息。页面里**没有一行外部资源引用** —— 没有外部字体、没有 CDN、没有统计脚本、没有埋点。
- **断网可用**：从本地双击打开时确实**不发起任何网络请求**；从网站上打开时，页面会自动改显示另一段说明 —— 服务器会记录常规访问日志（IP、访问时间、浏览器类型），但**不会记录您填写的内容**。
- **技术级保证**：部署配置里的 CSP 设了 `connect-src 'none'`，浏览器会**直接拦掉**页面发起的一切网络连接。这不只是承诺。
- 已填内容存在浏览器 localStorage，可随时用「重新开始」清空。
- 长图在本地 Canvas 上绘制，不经过任何服务器。

## 已知限制

- **内容由 AI 生成**，可能存在遗漏、误读或版本滞后，**未经医学专业人员审核**，不代表任何官方机构意见。
- 第 9–14 项标准未收录全文（收费出版物），因此老年模块的部分设计依据只能标到章节名，无法标条款号。
- 风险判定规则是对官方文件的**工程化转写**，不等于临床判断。74 / 75 岁以上、存在衰弱或预期寿命有限的人群，筛查决策必须由医生结合身体状况决定 —— 工具会提示这一点，但替代不了医生。
- 页面按桌面与移动浏览器做了响应式适配，但**未做完整的跨设备视觉回归测试**。
- 高发地区名单来自公开报道整理，**完整、权威的县级名单请以国家癌症中心公布的数据为准**。

## 二次开发

整个项目**只有一个文件**——根目录的 `index.html`。没有框架、没有构建步骤、没有依赖。想改什么直接改，改完刷新浏览器就行。

内部结构大致是这样：

| 名称 | 作用 |
|---|---|
| `STEPS` | 问卷全部步骤与题目（改问卷在这里） |
| `RISK_DEFS` | 18 类风险的判定规则、推荐项目、出处（改算法在这里） |
| `DEPT_BY_KEY` / `DEPT_TIPS` | 风险 → 科室映射、就诊提示 |
| `GLOSSARY` / `GLOSSARY_MORE` / `GLOSSARY_MORE2` / `GLOSSARY_MORE3` | 共 268 条术语解释与依据（157 条带依据文件原文摘录） |
| `DOCS` | 14 份依据文件的清单与元信息 |
| `buildPlan()` / `buildBriefPlan()` | 结果模型。**网页结果页和长图共用这一个数据源**，改一处两边同步 |
| `layoutResult()` / `drawOps()` | 长图的布局与绘制（Canvas 2D，两趟：先测量再绘制） |
| `docsHtml()` / `dlBlock()` | 依据文件栏目 |
| `goHome()` / `setView()` / `renderAbout()` | 视图切换 / 「关于·开源」页 |
| `REPO_URL` / `LICENSE_NAME` | 开源仓库地址与许可名称（页面上所有链接统一用这两个常量改） |
| `TAGLINE` | 一句话介绍（首页标语、关于页、`<meta name="description">` 三处保持一致） |

> ⚠️ **改 CSS 时注意：不要用裸元素选择器。**
> 页面里会动态注入 HTML（结果页、关于页、依据文件页），裸元素选择器会把这些注入内容一起命中。
> 例如原来底部导航写的是 `nav{position:fixed;bottom:0;background:#fff}`，
> 结果把结果页左侧目录的 `<nav class="rsidelist">` 也变成了「固定在屏幕底部、整屏宽、白底」的一整块，
> 直接盖住结果内容（v0.7–v0.9 的线上 bug）。
> 现在这类规则都写成了 `#nav` / `body > header`；`.rsidelist` 也加了显式复位做双保险。

**附件原文是注入进去的。** 页面里有一段被标记包裹的区域：

```
/*==DOCPAYLOAD_START==*/   …   /*==DOCPAYLOAD_END==*/
```

里面是 `DOCS_HTML`（带排版的附件 HTML）和 `DOCFILES`（原件的 base64）。更新了官方 .docx 之后，重新跑一次构建脚本即可重新注入，**不会动到其它代码**：

```bash
python build/生成附件原文.py      # 就地更新根目录的 index.html
```

脚本用到的库：`python-docx`、`Pillow`。

**内置的下载能力**：项目没有用任何 zip / docx 库。页面里自己实现了一个 ZIP 写入器（store 方式 + CRC32）和一个最小 .docx 生成器（`[Content_Types].xml` + `_rels/.rels` + `word/document.xml`），点下载时才生成，所以**不占文件体积**。

## 部署成网站

主程序是仓库根目录的 `index.html`。仓库里带了 [`netlify.toml`](./netlify.toml)，**导入后什么都不用配**。

### Netlify（推荐）

1. 用 GitHub 账号登录 [netlify.com](https://www.netlify.com)
2. **Add new site → Import an existing project** → 选 GitHub → 选这个仓库
3. 构建设置**不用改**（`netlify.toml` 已经写好）
4. 点 **Deploy**

之后每次 `git push` 自动重新部署。

`netlify.toml` 做了三件事：

| 设置 | 作用 |
|---|---|
| `command` + `publish = "dist"` | 构建时只把 `index.html` 拷进 `dist/` —— **5 个 .docx、研究报告、`build/` 都不上公网** |
| `Content-Security-Policy: … connect-src 'none'` | **从浏览器层面禁止页面发起任何网络连接**。"不上传您的信息"不只是承诺，浏览器会直接拦掉 |
| `Cache-Control: public, max-age=0, must-revalidate` | 每次访问都校验：改了立刻生效，没改走 304，不重复下载 806 KB |

另外还配了 `X-Content-Type-Options`、`Referrer-Policy: no-referrer`、`X-Frame-Options`、`Permissions-Policy` 等常规加固头。

> 如果构建那一步将来出问题：把 `netlify.toml` 里的 `command` 删掉、`publish` 改成 `"."`，就能变成零构建直接发布（代价是仓库文件都会公开）。

### ⚠️ Netlify 有两个特有的坑

**① 新站点默认「私有」，要手动发布一次**

Netlify 已改为 credits 计费，官方说明：*"On new credit-based pricing accounts, new projects start **private by default** and become publicly accessible only when you choose to publish."*

所以部署完如果**别人打不开**，回项目里点一下 **Publish**。

**② 免费额度按 credits 算，比 Vercel 紧得多**

免费版 **300 credits / 月**，各项**共用同一个池**：

| 项目 | 消耗 | 300 credits 能换到 |
|---|---|---|
| 生产部署 | 15 credits / 次 | 约 **20 次** |
| 带宽 | 20 credits / GB | 约 **15 GB** |
| Web 请求 | 2 credits / 万次 | 约 150 万次 |

举个实际例子：

> 一个月推 5 次代码（75 credits），剩 225 credits 全给带宽 ≈ 11 GB ≈ **2.4 万次访问**。

对这个体量的非营利工具够用，但**别频繁推送** —— 改一次推一次的话，20 次就把额度用光了。

### GitHub Pages（备用）

仓库 **Settings → Pages**，Source 选 `main` / `/(root)`，保存 → `https://<用户名>.github.io/<仓库名>/`。
（这条路径没有 `publish` 目录的概念，会把仓库所有文件都公开。）

### ⚠️ 关于中国大陆访问

**Netlify 与 Vercel、GitHub Pages 一样，都没有中国大陆节点**，大陆访问可能慢或打不开。这是托管地点的合规问题（境内托管需要 ICP 备案），**换平台解决不了**。

Vercel 官方对这件事的说明对 Netlify 同样适用：[Accessing Vercel-hosted sites from mainland China](https://vercel.com/kb/guide/accessing-vercel-hosted-sites-from-mainland-china) —— *"can't guarantee availability or performance within mainland China."*

**所以国内用户请直接下载 `index.html` 本地打开** —— 功能完全一样，而且断网也能用、不产生任何访问日志。
